## 4. `app/logging.py` — `configure_structlog` and `redact_authorization`

### 4.1 Module-level constants and imports

```python
import logging
from typing import Any, MutableMapping

import structlog
from structlog.types import EventDict, Processor, WrappedLogger

# Header values starting with "Bearer " are scrubbed; case-insensitive
# scheme match. We slice the token to its 12-char prefix where applicable
# so ops debugging retains the prefix that identifies the key.
_BEARER_SCHEME_LOWER: str = "bearer "
_REDACTED: str = "<redacted>"
_PREFIX_LEN: int = 12  # mirrors app.auth.PREFIX_LEN; see §4.4
```

Note: `_PREFIX_LEN` is duplicated here rather than imported from `app.auth` to avoid an import cycle (`app.auth` imports from `app.errors`; `app.logging` is imported indirectly during app construction). The constant is locked at 12 in both modules; if it ever needs to change, both locations move in lockstep. The Reviewer asserts both literals remain 12.

### 4.2 `configure_structlog(level: str) -> None`

```python
def configure_structlog(level: str) -> None:
    """Configure structlog + stdlib logging bridge for the gateway.

    All gateway log lines (structlog-emitted AND stdlib-`logging`-emitted
    via existing `logging.getLogger(...)` call sites) flow through the
    same processor chain and render as one-line JSON to stdout.

    Args:
        level: log level name; case-insensitive ("INFO", "info", "DEBUG"
            etc). Parsed via logging.getLevelNamesMapping(). Unknown
            levels fall back to logging.INFO.
    """
```

**Behavior**:

1. **Parse the level**. Use `logging.getLevelNamesMapping()` (Python 3.11+) to map a case-insensitive name to its int. Fallback to `logging.INFO` when the name is unrecognized; emit a one-time `_log.warning` to the bootstrap logger (stdlib, before configuration is finalized — the warning will be re-rendered as JSON once configuration completes for subsequent calls).

   ```python
   level_int: int = logging.getLevelNamesMapping().get(
       level.upper(), logging.INFO
   )
   ```

2. **Define the shared processor chain** (see §4.3 for ordering rationale):

   ```python
   shared_processors: list[Processor] = [
       structlog.contextvars.merge_contextvars,
       structlog.stdlib.add_log_level,
       structlog.processors.TimeStamper(fmt="iso", utc=True, key="ts"),
       structlog.processors.EventRenamer(to="event"),
       redact_authorization,
   ]
   ```

3. **Configure structlog** with the chain plus the JSON renderer at the tail:

   ```python
   structlog.configure(
       processors=[
           structlog.stdlib.filter_by_level,
           *shared_processors,
           structlog.stdlib.ProcessorFormatter.wrap_for_formatter,
       ],
       logger_factory=structlog.stdlib.LoggerFactory(),
       wrapper_class=structlog.make_filtering_bound_logger(level_int),
       cache_logger_on_first_use=True,
   )
   ```

   - `wrap_for_formatter` is the seam that hands the event_dict off to the stdlib `Formatter` so structlog and stdlib loggers share the JSON renderer.
   - `cache_logger_on_first_use=True` makes `structlog.get_logger(__name__)` cheap on the hot path.

4. **Bridge stdlib logging through the same chain**:

   ```python
   formatter = structlog.stdlib.ProcessorFormatter(
       foreign_pre_chain=shared_processors,
       processors=[
           structlog.stdlib.ProcessorFormatter.remove_processors_meta,
           structlog.processors.JSONRenderer(),
       ],
   )

   handler = logging.StreamHandler()  # default stream is sys.stderr;
                                       # see §4.7 for the stdout note.
   handler.setFormatter(formatter)

   root = logging.getLogger()
   # Replace any handlers added by a prior basicConfig() call so we
   # don't double-emit. Phase 1 still has logging.basicConfig in
   # app/main.py at lifespan-start; that line is removed in Phase 2 §6.
   root.handlers = [handler]
   root.setLevel(level_int)
   ```

   - `foreign_pre_chain` is the structlog processor list applied to records that originated from stdlib `logging.Logger`. With this set, `logging.getLogger("app.errors").error(...)` from the existing `app/errors.py:unhandled_exception_handler` flows through the SAME chain (including `redact_authorization`) before JSON rendering.
   - The `remove_processors_meta` processor drops the structlog-internal metadata keys (`_record`, `_from_structlog`) before rendering so the final JSON is clean.

5. **Return `None`**. The function is idempotent within a process (calling it twice replaces the root handlers with the new instance; the second call is rare in production but happens in tests under the `client` fixture).

### 4.3 Processor chain — exact order with rationale

| # | Processor | Why this order |
|---:|---|---|
| 1 | `structlog.contextvars.merge_contextvars` | Pulls any contextvars-bound state (e.g. `key_prefix` if the auth middleware ever uses `bind_contextvars` in a future iteration) into the event_dict. Cheap; runs first so subsequent processors see all bound context. |
| 2 | `structlog.stdlib.add_log_level` | Adds `level: "info"` (lowercase string) to the event_dict. Must run before `redact_authorization` so the redactor doesn't accidentally see `level` as a candidate key. |
| 3 | `TimeStamper(fmt="iso", utc=True, key="ts")` | Adds `ts: "2026-06-19T10:11:12.345Z"`. Spec §8 mandates `ts` (not `timestamp`); `key="ts"` enforces it. UTC matches the spec sample. |
| 4 | `EventRenamer(to="event")` | Maps structlog's default `event` key (the message string passed positionally) to the spec field name `event`. (`event` is already the default key name in modern structlog, but `EventRenamer` is the explicit seam used by the development plan §8 step 2.2; we keep it for documentation value and to match the plan verbatim.) |
| 5 | `redact_authorization` | Runs LAST in the shared chain so it sees the FINAL event_dict that will be rendered, including any auth-related fields injected by intermediate processors or by the call site. Defense-in-depth. |
| 6 | `JSONRenderer()` (in the formatter, NOT the shared chain) | Final renderer. The shared chain above does NOT include `JSONRenderer`; rendering happens in the `ProcessorFormatter`'s `processors=[..., JSONRenderer()]` tail so both structlog-native and stdlib-bridged records render identically. |

The plan §8 step 2.2 lists the processors as `add_log_level`, `TimeStamper(...)`, `EventRenamer(...)`, `redact_authorization`, `JSONRenderer()`. This architecture matches that ordering verbatim and adds `merge_contextvars` at the head as a forward-compatibility seam (zero behavior change in v0.2.0; documented for completeness).

### 4.4 `redact_authorization(logger, method_name, event_dict)`

```python
def redact_authorization(
    logger: WrappedLogger,
    method_name: str,
    event_dict: MutableMapping[str, Any],
) -> MutableMapping[str, Any]:
    """Scrub Authorization-bearing fields from a structlog event.

    Two distinct redaction rules are applied in a single pass:

    1. KEY-MATCH: any key whose lowercase form equals "authorization"
       has its value replaced with the redacted form (see below),
       regardless of the value's actual content. This catches the
       common pattern `_log.info("auth check", authorization=header)`.
    2. VALUE-MATCH: any STRING value (not a key) that starts with
       "Bearer " (case-insensitive on the scheme) has its content
       replaced with the redacted form. This catches values that
       leak through under different keys (e.g. a logged headers dict
       or a stringified Request repr).

    Redacted form:
       - When the value contains a token whose first PREFIX_LEN chars
         are extractable, emit "<redacted: {prefix}>" so ops debugging
         retains the prefix that ties the log line to a key in keys.db.
       - Otherwise emit the literal "<redacted>".

    Mutation policy: edits the event_dict in place AND returns it
    (structlog protocol). Nested dicts and lists are NOT walked
    recursively in v0.2.0 — only top-level keys and values are
    inspected. (See §4.6 for the rationale and known limitation.)
    """
```

**Algorithm (top-level only, single pass)**:

```python
def redact_authorization(logger, method_name, event_dict):
    for key in list(event_dict.keys()):
        value = event_dict[key]

        # Rule 1: key-match (case-insensitive).
        if key.lower() == "authorization":
            event_dict[key] = _scrub(value)
            continue

        # Rule 2: value-match — only on string values.
        if isinstance(value, str):
            stripped = value.lstrip()
            if stripped[:7].lower() == _BEARER_SCHEME_LOWER:
                event_dict[key] = _scrub(value)
    return event_dict


def _scrub(value: Any) -> str:
    """Replace a Bearer-bearing value with '<redacted: {prefix}>' when
    a 12-char prefix is extractable, else '<redacted>'."""
    if not isinstance(value, str):
        return _REDACTED
    stripped = value.lstrip()
    if stripped[:7].lower() == _BEARER_SCHEME_LOWER:
        token = stripped[7:].split()[0] if len(stripped) > 7 else ""
        if len(token) >= _PREFIX_LEN:
            return f"<redacted: {token[:_PREFIX_LEN]}>"
        return _REDACTED
    # Value matched the key rule but isn't itself a Bearer string;
    # scrub generically.
    return _REDACTED
```

**Locked behavior**:

- **Case-insensitive key match**: `Authorization`, `authorization`, `AUTHORIZATION`, `aUtHoRiZaTiOn` all match.
- **Case-insensitive scheme match**: `Bearer `, `bearer `, `BEARER ` all match.
- **Prefix preservation**: when the token is at least 12 characters long, the redacted form is `<redacted: {token[:12]}>`. For a token like `Bearer sk-local-AbCdEf...`, the redacted form is `<redacted: sk-local-AbC>`. For a malformed `Bearer x` token, the redacted form is `<redacted>` (no prefix to preserve).
- **In-place mutation + return**: required by the structlog processor protocol.
- **Single-pass / top-level only**: nested dicts and lists are NOT walked. Spec §8 + plan §9 ("Authorization redaction") describe this as defense-in-depth at the top-level event_dict; deeper recursion adds complexity for negligible win because v0.2.0 call sites do not log nested header dicts. Documented as a known limitation in §15 open question #2.
- **Non-string values under an `authorization` key**: scrubbed to the literal `<redacted>` (e.g., `_log.info("x", authorization=None)` becomes `authorization=<redacted>`).

## 5. `app/middleware_logging.py` — `RequestLoggingMiddleware`

### 5.1 Class signature

```python
import json
import time
from typing import Any

import structlog
from starlette.types import ASGIApp, Message, Receive, Scope, Send

_log = structlog.get_logger("app.middleware_logging")

# Paths whose JSON request body we attempt to parse for `model`.
# Anything else: model = None.
_BODY_INSPECT_PATHS: frozenset[str] = frozenset({
    "/v1/chat/completions",
    "/v1/embeddings",
})


class RequestLoggingMiddleware:
    """ASGI middleware that emits one structlog `request` event per HTTP
    request. Mounted AFTER BearerAuthMiddleware so scope['state']
    already carries `key_prefix`. Mounted BEFORE the routers so the
    timing window includes router work but EXCLUDES auth (auth is
    measured into latency_ms by virtue of running first).

    See architecture §6 for mount-order rationale.
    """

    def __init__(self, app: ASGIApp) -> None:
        self.app: ASGIApp = app

    async def __call__(
        self, scope: Scope, receive: Receive, send: Send
    ) -> None:
        ...  # see §5.2
```

**Why a pure ASGI class** (NOT a `BaseHTTPMiddleware` subclass):

1. `BaseHTTPMiddleware` buffers the entire response body before sending; this would break SSE streaming on `/v1/chat/completions`. We MUST pass `send` through untouched (or wrap it in a way that preserves chunk-by-chunk delivery).
2. We need to wrap `receive` to cache the request body bytes once (for `model` extraction) and re-emit them to the downstream handler. `BaseHTTPMiddleware` doesn't expose this cleanly.
3. We need to read `scope["state"]["key_prefix"]` set by Phase 1's `BearerAuthMiddleware` (an ASGI middleware), and adjacent ASGI middleware compose more cleanly than mixing ASGI + Starlette layers.

This matches Phase 1's `BearerAuthMiddleware` choice (Phase 1 architecture §5.1 reason 2).

### 5.2 `__call__` flow (numbered steps)

```
1.  If scope["type"] != "http":              pass through, return.
2.  start_time = time.perf_counter()
3.  path = scope["path"]
4.  Body cache (only when path is in _BODY_INSPECT_PATHS): wrap `receive`
    with a body-caching shim (see §5.3).
5.  Status capture: wrap `send` with a status-and-stream-capturing shim
    (see §5.4).
6.  Try: await self.app(scope, wrapped_receive, wrapped_send)
    Except Exception:
        # The downstream stack (exception handlers) should have
        # already produced a 500 response and called wrapped_send.
        # If not, status_holder.status defaults to 500.
        status_holder.status = status_holder.status or 500
        # Do NOT re-raise — log and continue. Actually, RE-RAISE so
        # uvicorn sees the failure (see §5.6). The re-raise happens
        # AFTER the finally block.
        raise
7.  Finally:
        latency_ms = int(
            (time.perf_counter() - start_time) * 1000
        )
        # Best-effort field extraction (each step swallows its own
        # errors and falls back to None / unknown):
        key_prefix = scope.get("state", {}).get("key_prefix")
        model = _extract_model(path, body_holder.body)
        backend = _resolve_backend(scope, model)
        stream_flag = _extract_stream(path, body_holder.body)
        usage = _extract_usage(path, status_holder)

        _log.info(
            "request",
            path=path,
            method=scope.get("method", "?"),
            status=status_holder.status,
            latency_ms=latency_ms,
            key_prefix=key_prefix,
            model=model,
            backend=backend,
            stream=stream_flag,
            prompt_tokens=usage.get("prompt_tokens"),
            completion_tokens=usage.get("completion_tokens"),
        )
```

**Field-by-field semantics** (see §11 for the locked decisions):

| Field | Source | When it's `None` |
|---|---|---|
| `path` | `scope["path"]` | never |
| `method` | `scope["method"]` | never |
| `status` | wrapped `send`'s observed `http.response.start` | request was canceled before any response start; default to 500 in that case (§5.6) |
| `latency_ms` | `time.perf_counter()` delta in ms (int) | never |
| `key_prefix` | `scope["state"]["key_prefix"]` | public path (auth never ran) or non-`/v1/*` path |
| `model` | parsed from cached request body (chat/embeddings only) | path not in `_BODY_INSPECT_PATHS`; body parse failed; body lacked `model` field |
| `backend` | `app.state.registry.get(model).backend` | model is None, or registry lookup returned None |
| `stream` | request body's `stream` field for `/v1/chat/completions`; always False for `/v1/embeddings`; None elsewhere | non-chat paths and parse failures |
| `prompt_tokens` / `completion_tokens` | response body's `usage` block (non-streaming); SSE `usage` field on the final non-`[DONE]` chunk (streaming, when present) | upstream did not emit `usage`; streaming response; parse failure |

### 5.3 **Body cache pattern (the LOAD-BEARING gotcha)**

The middleware MUST read the raw request body bytes ONCE (to extract `model` and `stream`) and then re-emit them to the downstream FastAPI router so the router sees an unconsumed body. The standard ASGI pattern: wrap `receive` to capture each `http.request` message's `body` bytes, accumulate them, then return a NEW `receive` callable that replays the captured messages on demand.

**Pseudocode (the Builder implements this verbatim, modulo Python style)**:

```python
class _BodyHolder:
    __slots__ = ("body", "complete")
    def __init__(self) -> None:
        self.body: bytes = b""
        self.complete: bool = False

# Inside __call__:
body_holder = _BodyHolder()
captured_messages: list[Message] = []

async def caching_receive() -> Message:
    """First pass: forward `receive` calls to upstream uvicorn AND
    cache the body bytes. Captured messages are NOT replayed on this
    pass — they are forwarded once.
    """
    message = await receive()
    if message["type"] == "http.request":
        body_holder.body += message.get("body", b"")
        if not message.get("more_body", False):
            body_holder.complete = True
        # Stash a copy so we could replay if needed.
        captured_messages.append(message)
    return message
```

**However** — the simplest correct approach is the well-known **single-shot replay** pattern:

```python
# Pre-read the entire body BEFORE calling self.app, then build a
# replay-receive that yields it as a single http.request message.

if path in _BODY_INSPECT_PATHS:
    body_chunks: list[bytes] = []
    more = True
    while more:
        message = await receive()
        if message["type"] != "http.request":
            # Unexpected (e.g. http.disconnect). Forward via a
            # synthesized replay and bail to the downstream app.
            captured_disconnect = message
            break
        body_chunks.append(message.get("body", b""))
        more = message.get("more_body", False)
    full_body = b"".join(body_chunks)
    body_holder.body = full_body

    replayed = False
    async def replay_receive() -> Message:
        nonlocal replayed
        if not replayed:
            replayed = True
            return {
                "type": "http.request",
                "body": full_body,
                "more_body": False,
            }
        # Subsequent calls (e.g. for keep-alive disconnects) just
        # delegate to the original receive.
        return await receive()

    wrapped_receive = replay_receive
else:
    wrapped_receive = receive
```

**Critical correctness notes**:

- **Body size cap**: an unbounded read is a DOS vector. v0.2.0 caps the cached body at **1 MiB** (`1024 * 1024` bytes). If the cumulative body exceeds the cap, the middleware ABANDONS the cache (sets `body_holder.body = b""`, switches `wrapped_receive = receive`, marks `model = None`) and the downstream handler reads the body normally. The 1 MiB cap is well above any realistic OpenAI chat/embeddings body (a 2K-token prompt encodes to ~10 KiB) and well below the default uvicorn / FastAPI body limit. The Reviewer asserts the cap constant is `1024 * 1024` and is referenced as a module constant `_MAX_CACHED_BODY: int = 1024 * 1024`.

- **`http.disconnect` mid-body**: if the client disconnects before `more_body=False`, the cache is incomplete. The middleware sets `model = None` and forwards the partial state. The downstream handler will see the disconnect normally.

- **Non-`_BODY_INSPECT_PATHS`**: skip the cache entirely, set `wrapped_receive = receive` directly. Saves the read-and-replay overhead on health probes etc.

- **GET requests** (no body): `_BODY_INSPECT_PATHS` only contains `POST` paths, so this is moot — but for safety, when `scope["method"] != "POST"`, skip the cache.

The Builder implements `_extract_model` and `_extract_stream` as small helpers that JSON-parse `body_holder.body` once and pull the relevant field, swallowing any `json.JSONDecodeError`, `UnicodeDecodeError`, `KeyError`, `TypeError`:

```python
def _extract_model(path: str, body: bytes) -> str | None:
    if path not in _BODY_INSPECT_PATHS or not body:
        return None
    try:
        parsed = json.loads(body.decode("utf-8"))
        if isinstance(parsed, dict):
            value = parsed.get("model")
            return value if isinstance(value, str) else None
    except (json.JSONDecodeError, UnicodeDecodeError):
        return None
    return None


def _extract_stream(path: str, body: bytes) -> bool | None:
    if path != "/v1/chat/completions" or not body:
        return None
    try:
        parsed = json.loads(body.decode("utf-8"))
        if isinstance(parsed, dict):
            value = parsed.get("stream", False)
            return bool(value) if isinstance(value, bool) else False
    except (json.JSONDecodeError, UnicodeDecodeError):
        return None
    return False
```

### 5.4 Status capture — wrapping `send`

```python
class _StatusHolder:
    __slots__ = ("status", "is_streaming", "first_body_chunk", "last_body_chunk")
    def __init__(self) -> None:
        self.status: int | None = None
        self.is_streaming: bool = False  # True if Content-Type is text/event-stream
        self.first_body_chunk: bytes = b""
        self.last_body_chunk: bytes = b""

status_holder = _StatusHolder()

async def capturing_send(message: Message) -> None:
    if message["type"] == "http.response.start":
        status_holder.status = message.get("status", 500)
        # Detect SSE so we attempt SSE usage parsing later.
        for name, value in message.get("headers", []):
            if name.lower() == b"content-type":
                if b"text/event-stream" in value.lower():
                    status_holder.is_streaming = True
                break
    elif message["type"] == "http.response.body":
        # Capture body for usage extraction. For non-streaming JSON
        # responses this is the full payload; for streaming this is
        # the per-chunk SSE bytes (we only need the LAST one).
        chunk: bytes = message.get("body", b"")
        if not status_holder.is_streaming:
            # Cap at 256 KiB; OpenAI completions are typically <50 KiB.
            if len(status_holder.last_body_chunk) + len(chunk) <= _MAX_CAPTURED_RESPONSE:
                status_holder.last_body_chunk += chunk
            else:
                status_holder.last_body_chunk = b""  # abandon
        else:
            # Streaming: only retain the most recent non-empty chunk;
            # we'll inspect it post-hoc for a `usage` field. The final
            # data chunk before "data: [DONE]\n\n" is the only one
            # Ollama emits a usage block on (when it does at all).
            if chunk.strip():
                status_holder.last_body_chunk = chunk
    await send(message)
```

The `_MAX_CAPTURED_RESPONSE` cap is `256 * 1024` (256 KiB). Streaming retention is one chunk only (the most recent non-empty one), so memory is bounded regardless of stream length.

The `await send(message)` is at the END of the wrapper — capture happens BEFORE the chunk is forwarded, so capturing never delays the client.

### 5.5 Usage capture — non-streaming AND streaming

**Non-streaming** (chat/embeddings): the response body is JSON of shape `{"choices": [...], "usage": {"prompt_tokens": int, "completion_tokens": int, "total_tokens": int}, ...}` (chat) or `{"data": [...], "usage": {"prompt_tokens": int, "total_tokens": int}, ...}` (embeddings). The middleware extracts `usage.prompt_tokens` and `usage.completion_tokens` (the latter is `None` for embeddings; that's correct).

```python
def _extract_usage(path: str, holder: _StatusHolder) -> dict[str, int | None]:
    out: dict[str, int | None] = {
        "prompt_tokens": None,
        "completion_tokens": None,
    }
    if not holder.last_body_chunk:
        return out
    if holder.is_streaming:
        return _extract_streaming_usage(holder.last_body_chunk)
    # Non-streaming JSON.
    try:
        parsed = json.loads(holder.last_body_chunk.decode("utf-8"))
        usage = parsed.get("usage") if isinstance(parsed, dict) else None
        if isinstance(usage, dict):
            pt = usage.get("prompt_tokens")
            ct = usage.get("completion_tokens")
            if isinstance(pt, int):
                out["prompt_tokens"] = pt
            if isinstance(ct, int):
                out["completion_tokens"] = ct
    except (json.JSONDecodeError, UnicodeDecodeError):
        pass
    return out
```

**Streaming** (chat only): Ollama's OpenAI-compatible SSE emits a sequence of `data: {json}\n\n` chunks, ending with `data: [DONE]\n\n`. When Ollama emits a `usage` block, it appears on the final non-`[DONE]` chunk. The middleware captures only the most recent non-empty chunk (§5.4); `_extract_streaming_usage` parses that chunk's JSON payload for a `usage` field.

```python
def _extract_streaming_usage(last_chunk: bytes) -> dict[str, int | None]:
    out: dict[str, int | None] = {
        "prompt_tokens": None,
        "completion_tokens": None,
    }
    text = last_chunk.decode("utf-8", errors="replace")
    # Find the LAST "data: " line that is not [DONE].
    candidate: str | None = None
    for line in text.splitlines():
        line = line.strip()
        if not line.startswith("data:"):
            continue
        payload = line[5:].strip()
        if payload == "[DONE]" or not payload:
            continue
        candidate = payload
    if candidate is None:
        return out
    try:
        parsed = json.loads(candidate)
        usage = parsed.get("usage") if isinstance(parsed, dict) else None
        if isinstance(usage, dict):
            pt = usage.get("prompt_tokens")
            ct = usage.get("completion_tokens")
            if isinstance(pt, int):
                out["prompt_tokens"] = pt
            if isinstance(ct, int):
                out["completion_tokens"] = ct
    except json.JSONDecodeError:
        pass
    return out
```

**LOCKED PUNT (development plan §5.2 explicitly allows this)**: when the upstream does NOT emit a `usage` block on the final SSE chunk (Ollama's behavior here is version-dependent), `prompt_tokens` and `completion_tokens` remain `None` and are emitted as JSON `null`. **Phase 2 makes a best-effort attempt at streaming usage capture; it does NOT fall back to retrieving `usage` from a separate Ollama API call, and it does NOT synthesize estimated counts.** Phase 3 tests assert this explicitly: a streaming completion that lacks an upstream `usage` block produces a `request` event with `prompt_tokens: null` and `completion_tokens: null`. This matches plan §5.2 ("if absent, the fields are omitted") and plan §11 Observability bullet ("non-streaming chat completions also carry `prompt_tokens` and `completion_tokens` when upstream emits a `usage` block").

Spec field-emission rule (locked): when token counts are unavailable, the middleware emits the keys with JSON `null` values, NOT omits them. Rationale: stable schema for downstream log consumers; the structlog event_dict naturally renders `None` as `null`. If a future ops requirement wants the keys omitted entirely, the middleware can call `event_dict.pop` in a tail processor — Phase 2 does NOT do this.

### 5.6 Backend resolution

```python
def _resolve_backend(scope: Scope, model: str | None) -> str | None:
    if model is None:
        return None
    # scope["app"] is the FastAPI instance (Starlette sets this on http
    # scopes that flow through a Starlette router). app.state.registry
    # is the current registry reference; reads are atomic.
    app = scope.get("app")
    if app is None:
        return None
    registry = getattr(app.state, "registry", None)
    if registry is None:
        return None
    found = registry.get(model)
    return found.backend if found is not None else None
```

The hot-reload swap is atomic (§8); a single `getattr(app.state, "registry", None)` is one Python attribute read and is safe even if a swap happens concurrently. The registry returned MAY be the new one (if the swap completes between the request entering and the logging middleware running its tail), which is acceptable for log fields — there is no semantic invariant that the logged `backend` must match what the router used. Phase 3 explicitly does not assert this invariant.

### 5.7 Failure containment

**The middleware MUST NOT raise from its own logic.** A bug in `_extract_model` or in the structlog event emission MUST NOT 500 the request. Rules:

1. Each helper (`_extract_model`, `_extract_stream`, `_extract_usage`, `_resolve_backend`) wraps its own try/except and returns `None` on failure.
2. The final `_log.info("request", ...)` call is wrapped in a top-level `try/except Exception as exc:`. On failure, fall back to a degraded emission:
   ```python
   try:
       _log.info("request", ...all fields...)
   except Exception as exc:  # noqa: BLE001 — defense in depth
       try:
           # Last-ditch: bypass structlog and use the stdlib root
           # logger directly. This ALSO flows through the bridge,
           # so it's still JSON, but it eliminates dependency on
           # any custom processor that may have raised.
           logging.getLogger("app.middleware_logging").error(
               "request_log_failed",
               extra={"err": str(exc)},
           )
       except Exception:
           pass  # truly nothing we can do; never raise upward
   ```
3. The downstream handler's exception (if any) is captured by `app/errors.py` and translated to a 500 envelope; the middleware sees the 500 status via the wrapped `send` and logs it normally. The middleware does NOT swallow the downstream exception — it lets the FastAPI exception handler stack handle it, and the wrapped `send` records the resulting status code.

The middleware's `__call__` therefore propagates downstream exceptions (the FastAPI exception handlers will handle them and emit a response, after which the wrapped `send` records the status). It catches its OWN logic exceptions in each helper and at the final emit site.

**Specifically**: the `await self.app(scope, wrapped_receive, wrapped_send)` call is NOT wrapped in a try/except in the middleware. Any exception that propagates from there is re-raised after the finally block runs (the finally block emits the log line with whatever status was captured, defaulting to 500 if no `http.response.start` arrived). This matches Starlette's middleware contract: middleware MUST propagate ASGI exceptions or uvicorn's error handling breaks.

### 6.2 Why `RequestLoggingMiddleware` is added AFTER `BearerAuthMiddleware`

In Starlette, **`add_middleware` reverses the order of execution**: middleware added LATER wraps CLOSER to the app (i.e., runs LATER on request and EARLIER on response). With the order above, the request flow is:

```
client
  → exception-handler-stack (outer wrap, registered via install_exception_handlers)
  → BearerAuthMiddleware   (added 1st; outermost middleware; runs FIRST on request)
  → RequestLoggingMiddleware (added 2nd; runs after auth on request)
  → router
```

This is the exact order required:

- **Auth runs first on request**: so `scope["state"]["key_prefix"]` is set BEFORE `RequestLoggingMiddleware` reads it.
- **Logging runs last on request, first on response**: so `latency_ms` includes the router work but EXCLUDES the auth verify cost. **This is a deliberate choice**: per the development plan §9 "Middleware install order" cell, "Auth fires before logging so `key_prefix` is bound onto the scope state by the time logging reads it." The plan does NOT require auth latency to be measured into `latency_ms`; the field is documented as the request handling latency, not the full wire-to-wire round-trip. Phase 3 tests assert that `latency_ms` is positive and bounded above by a sane upper bound; they do NOT assert it includes the ~50 ms Argon2 verify cost.

  **Wait — re-reading the input contract**: the input contract says "logging is last so latency includes auth time". This contradicts my read. Let me re-check the §9 plan text: "Auth fires before logging so `key_prefix` is bound onto the scope state by the time logging reads it." — this is silent on whether latency includes auth. **The input contract is authoritative**: "logging is last so latency includes auth time".

  **Resolved**: with `add_middleware(BearerAuth)` then `add_middleware(RequestLogging)`, RequestLogging is INNER (closer to the router). Therefore on a request, BearerAuth runs first, then RequestLogging. RequestLogging starts its `time.perf_counter()` AFTER auth has already verified — so `latency_ms` does NOT include auth time.

  **To make `latency_ms` include auth time**, the order must be reversed: `add_middleware(RequestLogging)` first (outer), then `add_middleware(BearerAuth)` (inner). Then on request: RequestLogging starts the timer → BearerAuth verifies → router → response → BearerAuth → RequestLogging stops the timer and emits.

  But then RequestLogging cannot read `scope["state"]["key_prefix"]` until AFTER auth has run, which it cannot, because auth runs INSIDE RequestLogging in this ordering. Solution: RequestLogging reads `scope["state"]["key_prefix"]` in its FINALLY block (i.e. after `await self.app(...)` returns), at which point BearerAuth has already populated it. The middleware reads scope state at LOG EMIT time, not at request entry — so this works.

RequestLogging starts timing on the way in and reads `scope["state"]["key_prefix"]` on the way out, where it has been populated by BearerAuth. `latency_ms` therefore INCLUDES auth verify time, matching the input contract.

### 7.2 Implementation flow

```python
adapters = request.app.state.adapters  # {backend_name: BackendAdapter}
names = sorted(adapters.keys())  # deterministic order in the response

results = await asyncio.gather(
    *(adapters[name].health() for name in names),
    return_exceptions=True,
)

backends: dict[str, Any] = {}
any_ok = False
for name, result in zip(names, results):
    if isinstance(result, BaseException):
        # Exception during health() — most commonly a NotSupportedError
        # from the MLX/DMR stub. Map to a uniform error payload.
        backends[name] = {
            "status": "error",
            "error": _short_error(result),
        }
    elif isinstance(result, dict):
        backends[name] = result
        if result.get("status") == "ok":
            any_ok = True
    else:
        # Defensive: an adapter returned something other than a dict.
        # Map to the same error shape so the contract holds.
        backends[name] = {
            "status": "error",
            "error": f"unexpected health() return type: {type(result).__name__}",
        }

if any_ok:
    return JSONResponse(
        status_code=200,
        content={"status": "ok", "backends": backends},
    )

# All backends down — emit the OpenAI envelope WITH the per-backend
# detail nested under a non-spec field so ops still sees what failed.
envelope = make_error(
    type_="service_unavailable",
    message="No backends reachable",
    param=None,
    code="no_backends_reachable",
)
envelope["backends"] = backends  # spec-extension; ops ergonomics
return JSONResponse(status_code=503, content=envelope)
```

## 8. `app/registry_watcher.py` — `start_registry_watcher`

### 8.1 Function signature

```python
import asyncio
from typing import TYPE_CHECKING

import structlog
from watchfiles import awatch

from app.registry import RegistryError, load_registry

if TYPE_CHECKING:
    from fastapi import FastAPI
    from app.config import Settings

_log = structlog.get_logger("app.registry_watcher")


def start_registry_watcher(
    app: "FastAPI",
    settings: "Settings",
) -> asyncio.Task[None]:
    """Start a background asyncio task that watches the models YAML
    file and atomically swaps app.state.registry on every successful
    reload.

    Returns:
        The task handle. The lifespan caller is responsible for
        cancelling it on shutdown (cancel() + await; CancelledError
        is swallowed).
    """
    return asyncio.create_task(
        _watch_loop(app, settings),
        name="registry-watcher",
    )


async def _watch_loop(app: "FastAPI", settings: "Settings") -> None:
    """The actual watch loop. Cancellation is propagated naturally
    from awatch's async-iterator protocol — when the surrounding task
    is cancelled, the awatch generator's __aexit__ fires and the
    underlying watcher thread is stopped."""
```

### 8.2 `awatch` configuration

```python
async def _watch_loop(app, settings):
    path = str(settings.models_yaml_path)
    _log.info("registry_watcher_started", path=path)

    try:
        async for changes in awatch(
            path,
            # No stop_event needed — task cancellation handles shutdown.
            # awatch debounces by default (50ms step); we DO NOT need
            # to add our own debouncing.
            recursive=False,
            # rust_timeout=200ms (default) — fine.
            # watch_filter=DefaultFilter() — fine; default filters out
            # transient editor swap files.
        ):
            # `changes` is a set of (Change, str) tuples. We don't
            # inspect them — any change triggers a reload attempt.
            await _try_reload(app, path)
    except asyncio.CancelledError:
        _log.info("registry_watcher_cancelled")
        raise  # propagate cancellation to the lifespan caller.
    except Exception as exc:
        # Unexpected error from watchfiles (filesystem permission,
        # etc.). Log and exit the loop; the lifespan task will be
        # marked failed but the gateway keeps serving with the
        # registry it has.
        _log.error(
            "registry_watcher_crashed",
            error=str(exc),
            error_type=type(exc).__name__,
        )
        raise
```

**Flag rationale**:

- `recursive=False`: we watch a single file; recursion is unnecessary and would expand the watch surface to the parent directory.
- No `stop_event`: `asyncio.create_task(...).cancel()` handles cancellation cleanly via `CancelledError` flowing through the `async for` generator.
- No custom `step` (debounce window): `awatch`'s default 50 ms is appropriate; editor saves often produce write-then-rename burst events, and 50 ms is enough to coalesce them.
- No custom `watch_filter`: `DefaultFilter` already excludes common editor temp files (`.swp`, `.~lock`, etc.). YAML files don't trigger any of the default exclusions.

### 8.3 Reload flow — `_try_reload`

```python
async def _try_reload(app, path: str) -> None:
    """Attempt to load the registry from disk. On success: atomic
    swap app.state.registry. On failure: log and keep the previous
    registry."""
    try:
        # load_registry is synchronous but cheap (small YAML, no
        # network). We call it directly without to_thread because
        # the YAML files are small and the reload happens at most
        # once per ~50ms (debounce).
        new_registry = load_registry(path)
    except FileNotFoundError as exc:
        _log.warning(
            "registry_reload_failed",
            reason="file_not_found",
            path=path,
            error=str(exc),
        )
        return
    except RegistryError as exc:
        _log.warning(
            "registry_reload_failed",
            reason="parse_error",
            path=path,
            error=str(exc),
        )
        return
    except Exception as exc:
        # yaml.YAMLError, OSError, etc.
        _log.warning(
            "registry_reload_failed",
            reason="unexpected_error",
            path=path,
            error=str(exc),
            error_type=type(exc).__name__,
        )
        return

    # Atomic ref swap. Python attribute assignment on an object is
    # one bytecode op (STORE_ATTR); concurrent reads always see
    # either the old or the new reference, never a torn one.
    old_registry = app.state.registry
    app.state.registry = new_registry

    if new_registry.ids() == old_registry.ids():
        # No model-id change — common case for editor formatting
        # changes (whitespace, comment edits, key reordering).
        # Still log so ops can see the watcher is alive.
        _log.info(
            "registry_reloaded_unchanged",
            path=path,
            n_models=len(new_registry.models),
        )
    else:
        _log.info(
            "registry_reloaded",
            path=path,
            n_models=len(new_registry.models),
            old_ids=old_registry.ids(),
            new_ids=new_registry.ids(),
        )
```

### 8.4 Atomicity guarantee

Python's `app.state.registry = new_registry` is a single `STORE_ATTR` bytecode operation against the underlying `dict.__setitem__` of `app.state.__dict__`. CPython's GIL ensures this is atomic relative to concurrent `LOAD_ATTR` reads from any other coroutine.

**In-flight request semantics**:

```
T0: request A enters chat.py
    → registry = request.app.state.registry  (snapshot of OLD)
    → registry.get(body.model)              (reads OLD)
T1: registry watcher reloads YAML, swaps:
    app.state.registry = new_registry        (STORE_ATTR — atomic)
T2: request A continues with `registry`     (still OLD; no torn read)
T3: request B enters chat.py
    → registry = request.app.state.registry  (snapshot of NEW)
```

Routers read `request.app.state.registry` ONCE at the top of the handler (per the existing v0.1.0 idiom in `app/routers/{chat,embeddings,models}.py`); subsequent uses inside the handler reference the local `registry` variable, which holds the snapshot. The swap therefore cannot affect an in-flight request.

`Registry` itself is `@dataclass(frozen=True, slots=True)` (Phase 1 left this unchanged), so even if a hypothetical handler kept a long-lived reference, the object is immutable. No torn reads are possible.

### 8.5 Limitations — adapters are FROZEN at startup

**Locked v0.2.0 limitation (development plan §9 "Hot-reload scope")**:

The watcher does NOT call `build_adapters(...)` after a reload. `app.state.adapters` remains the dict constructed at startup. Consequences:

| Reload scenario | Behavior | Outcome |
|---|---|---|
| Add a model with `backend: ollama` (already constructed) | New model id available in registry | works — `/v1/models` shows it; chat/embeddings can target it |
| Edit a model's `upstream_model` | new mapping visible at next handler entry | works |
| Edit a model's `capabilities` | new gates apply at next handler entry | works |
| Remove a model | not visible in registry | works — request to that id returns 404 |
| Add a model with a NEW backend (e.g., first-ever `mlx` entry where startup had no MLX models) | registry contains the new model but `app.state.adapters` has no `mlx` key | **FAILS with KeyError when a request hits the new model** — see §8.6 mitigation |
| Change a model's `base_url` | registry's `Model.base_url` updates but the adapter's `httpx.AsyncClient` was constructed with the OLD URL | new value is in registry but adapter ignores it |

**Mitigation for the new-backend case**: the routers' adapter lookup `adapters[model.backend]` would `KeyError` on a request to a model whose backend wasn't constructed at startup. This is an existing v0.1.0 + v0.2.0 surface (the same KeyError would happen if `models.yaml` were edited at startup with a typo'd backend name; though `build_adapters` would have caught it via its own validation). We do NOT add a try/except around the lookup in v0.2.0; the resulting 500 from the catch-all handler is acceptable for a known-limitation v0.2.0 path.

Documented in plan §9 ("adding a new backend type would require adapter construction — out of scope for v0.2.0; documented as a known limitation"). The README update in Phase 3 surfaces this to users.

### 8.6 Cancel-safety

The lifespan shutdown (§6.3) does:

```python
watcher_task.cancel()
try:
    await watcher_task
except asyncio.CancelledError:
    pass
```

Inside `_watch_loop`, `CancelledError` propagates through the `async for changes in awatch(...)` generator. `awatch` is implemented in `watchfiles` to handle cancellation by stopping its underlying Rust thread and aborting the next `__anext__` call — so cancellation cleanly tears down the OS-level inotify/kqueue watcher.

The `_log.info("registry_watcher_cancelled")` line emits a final shutdown event before the `CancelledError` re-raises. This is observable in logs and asserted by Phase 3 (the lifespan test asserts the watcher emits a cancelled event on shutdown).

Edge case: if cancellation arrives WHILE `_try_reload` is mid-flight (e.g., `load_registry` is parsing a large YAML), the `CancelledError` will be raised at the next `await` point. Because `_try_reload` is fully synchronous (no `await` inside), cancellation cannot interrupt it — it completes naturally, then the `async for` exits. This is fine: the swap is atomic; either it completed or it didn't, and either way the lifespan caller sees `CancelledError` via the awaited task.

### 8.7 Watcher does NOT block startup

`asyncio.create_task(...)` schedules the task without awaiting it. The lifespan continues immediately to `yield`, so server startup is NOT delayed by `awatch`'s initial enumeration. The watcher emits `event="registry_watcher_started"` before its first `async for` iteration, which is observable in logs.

If `awatch` itself fails synchronously at construction (e.g., the file path doesn't exist — which `load_registry` would have already caught at startup, so this is effectively unreachable), the failure surfaces when the task is awaited at shutdown via the `Exception` branch in `_watch_loop`. Phase 3 does not test this path explicitly.

### 8.8 Reviewer assertions

- `app/registry_watcher.py` exports `start_registry_watcher(app, settings) -> asyncio.Task[None]`.
- The function returns an `asyncio.Task` that has been scheduled (not yet awaited).
- `_try_reload` catches `FileNotFoundError`, `RegistryError`, and `Exception`, in that order, and emits `event="registry_reload_failed"` for each (with a `reason` field discriminating between them).
- A successful reload emits `event="registry_reloaded"` (or `event="registry_reloaded_unchanged"` when ids are unchanged) with `n_models` and (for the changed case) `old_ids` / `new_ids`.
- The function does NOT call `build_adapters(...)`.
- The atomic swap is `app.state.registry = new_registry` (one statement, no intermediate mutation).

## 9. Mount-order rationale (cross-reference §6)

Restated for the Reviewer's locked checklist:

| Layer (outer → inner) | Component | Reason |
|---|---|---|
| 1 (outermost) | Exception handler stack (registered by `install_exception_handlers`) | Catches any exception that escapes middleware OR routers and emits an OpenAI envelope. Must be outermost so middleware-emitted responses (401, 503) are NOT re-handled. |
| 2 | `RequestLoggingMiddleware` | Times the full request including auth verify; reads `key_prefix` from scope state in its FINALLY block, AFTER auth has populated it. |
| 3 | `BearerAuthMiddleware` | Verifies the bearer token, attaches `key_prefix` to `scope["state"]`. |
| 4 (innermost) | Routers (`/healthz`, `/readyz`, `/v1/*`) | Application logic. |

`add_middleware` order: `install_exception_handlers(app)` → `app.add_middleware(RequestLoggingMiddleware)` → `app.add_middleware(BearerAuthMiddleware, keys_db_path=...)` → `app.include_router(...)`.

**Why exception handlers don't intercept middleware-emitted JSONResponses**: in Starlette, `app.add_middleware(...)` and `app.add_exception_handler(...)` install at different layers. Exception handlers wrap the outermost layer of the FastAPI app's call stack and only fire when an exception is RAISED — they do not intercept normal `JSONResponse` returns from a middleware. So the 401 from `BearerAuthMiddleware._reject(...)` and the 503 from `/readyz` flow through `RequestLoggingMiddleware` (which logs them) and out to the client, exactly as we want.
